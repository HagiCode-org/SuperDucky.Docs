模组没有生效时,最直接的线索在游戏日志里。“日志系统”页面可以在 SuperDucky 里实时读取当前游戏的日志,不用自己去找日志文件。

![日志系统页面正在监控逃离鸭科夫的日志,列出每个模组的加载信息](../img/screenshots/user-guide/game-log-zh-cn/original.avif)

## 使用

1. 点击导航栏的**日志系统**。
2. 点击**开始监控**,页面右上角出现“监控中”的标记,新的日志行会实时追加。
3. 需要停下来看时点击**停止监控**。

工具栏上的按钮:

| 按钮 | 作用 |
|------|------|
| **停止监控** | 暂停读取新的日志 |
| **清空** | 清空页面上显示的内容 |
| **编辑器** | 在编辑器中打开日志文件 |
| **文件夹** | 打开日志所在的文件夹 |
| **顶部 / 底部** | 跳到日志的开头或结尾 |
| **搜索日志** | 只显示包含关键词的行 |
| **自动滚动** | 开启后始终停在最新的一行 |

页面底部显示监控状态、当前显示的行数(例如 `18 / 18`)和日志大小。

## 怎么读

:::note
截图中的日志是演示数据,不是游戏真实的输出格式。真实日志的内容取决于游戏和各个模组。
:::

排查模组问题时,可以这样用日志:

- **按模组名搜索**:在搜索框里输入模组名,页面只显示相关的行,同时显示匹配的条数。找不到任何一行,往往说明游戏根本没有发现这个模组,先回到“模组管理”确认它已启用并保存。
- **看加载的先后**:各个模组的加载记录出现的先后,就是实际的加载顺序,可以和“预览结果”对照。
- **找错误和异常**:搜索 `error`、`exception` 或模组名,出错的信息通常紧挨着对应模组的加载记录。
- **看有没有走到最后**:游戏正常启动后日志会持续增长。日志停在中途,说明某个模组或游戏本身在那里出了问题。

三个游戏的日志位置不同,SuperDucky 会自己找到它。如果页面是空的,先确认游戏已经启动过一次,并且在[设置](/user-guide/settings)里配置了游戏数据路径(逃离鸭科夫)、存档目录(深空当铺)或游戏数据目录(以撒的结合)。

以撒的结合的日志通常是游戏数据目录里的 `log.txt`。这个位置尚未在真机上核实,详见[以撒的结合](/user-guide/isaac)。

## SuperDucky 自己的日志

SuperDucky 本身的运行日志与游戏日志是分开的。在“设置 → 调试工具”里可以调整日志级别(DEBUG、INFO、WARN、ERROR)、日志轮转,打开日志文件夹,或**导出最近日志 / 导出全部日志**,反馈问题时附上导出的日志会很有帮助。
