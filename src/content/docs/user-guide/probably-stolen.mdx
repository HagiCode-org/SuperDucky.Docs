SuperDucky 同样支持《深空当铺》(Probably Stolen)。分组、启用、预览和套件的用法与逃离鸭科夫完全一样,不同之处主要在模组格式和启动时的**能力确认**。

先在导航栏顶部的“当前游戏”里切换到“深空当铺”;第一次切换需要完成这个游戏的初始化,见[首次启动](/quick-start/first-launch)。

![深空当铺的模组管理页面:Shop helpers 分组显示三个模组,其中两个带有“能力”标记](../img/screenshots/user-guide/probably-stolen-mods-zh-cn/original.avif)

## 模组格式

深空当铺的模组是一个文件夹,里面有 `manifest.xml`,包含 `<ID>`、`<Name>`、`<ModVersion>`、`<Assemblies>` 和 `<Capabilities>`。本地模组放在游戏目录下的 `Mods` 文件夹,创意工坊模组放在 Steam 的创意工坊文件夹里。

SuperDucky 对清单的检查比较严格:

- 清单里**没有 `<Capabilities>`** 的模组不能启用,因为游戏会拒绝它;
- **同一个 `<ID>` 出现在两个位置**时,两个模组都会被标记为冲突,都不能启用,需要先移除其中一个。

## 能力

“能力”是模组在清单里声明的、需要游戏授权的权限。带有能力的模组,卡片上会显示“能力:N”的标记,鼠标悬停可以看到具体列表。

![深空当铺的预览结果:五个模组按分组着色,卡片上显示各自的能力数量](../img/screenshots/user-guide/probably-stolen-all-groups-zh-cn/original.avif)

| 能力 | 含义 |
|------|------|
| 文件访问 | 可以读写本机文件 |
| 网络 | 可以访问网络 |
| 启动进程 | 可以启动其它程序 |
| 运行动态代码 | 可以在游戏运行时生成并执行代码 |
| 原生代码 | 可以加载原生(非托管)库 |
| 其它程序集 | 可以通过反射读取其它程序集的内部成员 |
| Steam | 可以调用 Steam 客户端接口 |
| 未知能力 | 无法识别的能力,只有在信任该模组时才允许 |

## 启动时的确认

在模组管理页面里切换开关只改变当前套件。点击**启动游戏**时,SuperDucky 会先规划同步,再决定要不要询问你:

1. 如果有模组**新启用**并声明了能力,会弹出“确认模组能力”对话框,逐个列出这些模组和它们的能力;
2. 对已经启用的模组,只有当清单里出现了此前没有批准过的**新能力**时才会再次询问;能力减少或没有变化时不会打扰你;
3. 每个模组需要**单独勾选**“我已了解这些能力,并允许该模组使用它们”,没有“全部批准”,也不会记住批准;
4. 全部勾选后点击**确认并启动**。点击**取消**则什么都不会写入,游戏也不会启动。

## 存档与备份

SuperDucky 通过修改游戏存档 `SaveFile.es3` 来启用、禁用和排序模组,只改动三个顶层字段(加载顺序 `modOrder`、信任记录 `modTrust`,并删除签名 `modTrustMac` 让游戏重新签名),其余内容原样保留。

- 每次写入前,存档会先复制为 `SaveFile.es3.superducky-bak-<时间戳>`,保留最近 10 份。
- 新内容先写入临时文件,读回校验后再替换原文件。
- 如果存档不是预期的格式(例如有 BOM、不是 UTF-8、顶层有重复字段),SuperDucky 会**拒绝写入**,不会尝试修复。
- 游戏正在运行时拒绝写入。看到“深空当铺正在运行,请先关闭游戏再启动”时,先退出游戏。如果无法判断游戏是否在运行,也会按“在运行”处理。

## 创意工坊模组

深空当铺的创意工坊模组可以启用,写入存档的记录会标明它来自创意工坊。目前这类模组还没有在真机上完整验证,界面上会标注“未经真机验证”,启动后也会提示。

## 和逃离鸭科夫的区别

| 功能 | 逃离鸭科夫 | 深空当铺 |
|------|-----------|----------|
| 模组清单 | `info.ini` | `manifest.xml` |
| 创意工坊市场 | 有 | 有 |
| 游戏日志 | 有 | 有 |
| 能力确认 | 无 | 有 |
| 存档图鉴 | 有 | 无 |
| NuGet 市场 | 有 | 无 |
| BML 导入 | 有 | 无 |
| 启动器依赖检查 | 有 | 无 |
| 同步失败时 | 仍然启动游戏 | 阻止启动 |
