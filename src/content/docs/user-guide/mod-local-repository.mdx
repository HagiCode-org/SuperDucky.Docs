模组本地仓库在这台电脑上为每个模组保存它出现过的每个版本,来源包括 Steam 创意工坊和游戏的本地 `Mods` 文件夹。它的用途是回看一次更新改了什么;更新弄坏模组时,你也能找到更早的版本。

它只做保存和查看。游戏加载的始终是模组文件夹里的当前内容,SuperDucky 不会替你切换到旧版本。唯一会把已保存版本放回模组文件夹的是[固化的套件](/user-guide/load-order-and-profiles),而且只在启动时发生。

![模组本地仓库页面:列出已归档的模组,每个模组一张卡片](../img/screenshots/user-guide/mod-local-repository-list-zh-cn/original.avif)

## 在哪里找到

- 导航栏里的**模组本地仓库**,位于**模组管理**之后。每个游戏都有这一项;游戏完成初始化之前它不可用。
- 游戏的“设置”页面里也有一段“模组本地仓库”,包含开关和打开仓库页面的入口。

## 开关默认关闭

模组本地仓库按游戏单独设置,默认关闭。关闭期间,SuperDucky 不归档任何内容,也不运行定时比对。

打开后:

- SuperDucky 按间隔比对模组,发现新版本就归档。间隔默认是 60 分钟,可以设为 5 到 1440 分钟之间的整数。
- 点击**立即检查**可以马上比对一次。开关关闭时无法立即检查,页面会提示先打开开关。

| 界面文字 | 位置 |
|----------|------|
| 保留创意工坊模组和本地模组的版本历史 | 设置里的开关 |
| 默认关闭。关闭期间,DML 不归档任何内容,也不运行定时比对。 | 开关下方的说明 |
| 每隔 | 间隔输入框前的文字 |
| 分钟比对一次(5 到 1440) | 间隔输入框后的文字 |
| 立即检查 | 设置和仓库页面上的按钮 |

:::note
界面文字里的“DML”指的就是 SuperDucky 本身,这是应用的旧名称。
:::

## 仓库页面

- **关闭时**:页面说明模组本地仓库是什么,并提供**开启模组本地仓库**按钮。之前已经归档过的模组仍然可以查看,但只读,并标注“关闭期间不会归档新内容”。
- **打开时**:顶部显示总量,然后是**立即检查**和每个已保存模组的一行。点开一行可以看到这个模组的版本历史。

![一个模组的版本历史:列出每个已归档版本的指纹和模组声明的版本](../img/screenshots/user-guide/mod-local-repository-versions-zh-cn/original.avif)

## 版本如何区分

- **每个版本由内容指纹标识。** 内容相同的重复比对不会新增版本。
- **版本时间是 SuperDucky 归档它的时间**,使用本地时间,不是作者发布模组的时间。作者写的版本号只作为次要文字显示。
- **回到已归档的版本时直接复用。** 如果模组文件夹又变回一个已经保存过的版本,SuperDucky 使用已保存的那一份,不会再存一份副本。
- **当前内容还没归档时,列表最前面会有一行单独标注:** “Steam 当前版本，尚未归档”或“模组文件夹中的当前版本，尚未归档”。这一行没有时间。

## 不会因为时间而删除

- 已保存的版本不会因为久远、长期未使用或很久没有在 Steam 中出现而被删除。没有任何定时任务会删除它们。
- SuperDucky 没有删除已归档版本的操作。
- 页面上的“仓库大小”显示当前占用的空间。

## 使用限制

- **只读取原始文件夹。** SuperDucky 从 Steam 文件夹和本地 `Mods` 文件夹复制内容,从不修改它们。
- **依赖随附的 Git。** 归档使用随 SuperDucky 一起提供的 Git。如果它无法运行,仓库会暂停:不归档,也不读取,页面会说明原因。
- **损坏的仓库只影响一个模组。** 如果某个模组的仓库无法读取,页面只为那个模组报告问题。它保持原样,不会被修复、重建或删除。
- **不能手动选择旧版本加载。** 目前还没有“切换到这个版本”的功能。
