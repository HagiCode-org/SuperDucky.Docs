SuperDucky 支持《以撒的结合》(The Binding of Isaac,Steam 应用 ID 250900)。Rebirth、Repentance 和 Repentance+ 在这里被视为同一个游戏。它的模组管理和另外两款游戏大体相同,但有两处明显不同:**没有加载顺序**,也**没有能力确认**。

第一次切换到这个游戏时需要完成初始化,见[首次启动](/quick-start/first-launch)。

:::note
本页中凡写“通常”“一般”的内容,是根据游戏文件和常见做法得出的,尚未在真机上核实。Linux 上的数据目录、模组副本目录、启用与停用的效果、日志位置和进程名已在真机上核实(见下文)。Windows 上的路径和行为没有在真机上核实。SuperDucky 无法读取游戏实际加载了哪些模组。
:::

## 模组格式

以撒的结合的模组是一个文件夹,里面有 `metadata.xml`。SuperDucky 从中读取名称、目录名、`<id>`、版本和标签,只读这个文件,不读取模组里的 Lua 代码。

- **本地模组**放在游戏安装目录下的 `mods` 文件夹里,每个模组一个子文件夹。游戏是否会在 Linux 上加载这个文件夹尚未核实。
- **创意工坊模组**订阅后放在 Steam 的创意工坊内容文件夹 `steamapps/workshop/content/250900/` 里,每个模组是一个以工坊编号命名的文件夹。在 Linux 上,游戏实际加载的是它复制出来的副本,见下面的“启用与停用”。

SuperDucky 用模组的身份区分模组。本地模组的身份是 `metadata.xml` 中的 `<id>`,没有就用 `<directory>`,再没有就用文件夹名;创意工坊模组的身份是文件夹名,也就是工坊编号。

- `metadata.xml` 缺少 `<id>` 时会给出警告。文件损坏或读不出身份的模组会被标为无效,不能启用。
- 同一个模组同时出现在本地和创意工坊、身份相同时,两份都会被标为冲突,都不能启用。需要先移除其中一份。

## 路径

以撒的结合是原生游戏,SuperDucky 不使用 Proton 前缀。

- **游戏数据目录**(设置里的“游戏数据目录”):保存存档、日志和游戏设置的文件夹。Linux 上是 `~/.local/share/binding of isaac afterbirth+/`。Windows 上通常是 `%UserProfile%\Documents\My Games\Binding of Isaac Repentance+\`(Windows 路径未经真机验证)。
- **模组副本目录**(只在 Linux 上存在):与游戏数据目录并排的 `~/.local/share/binding of isaac afterbirth+ mods/`。游戏把每个创意工坊模组复制到这里,并且只从这里加载。SuperDucky 根据游戏数据目录找到它,它不在设置里;只有这个文件夹已经存在时才会被检测到。
- **安装目录和创意工坊目录**:SuperDucky 通过 Steam 的库目录自动检测。
- **本地 mods 文件夹**:只有它已经存在时才会被自动检测到。如果没有检测到,请在设置中手动选择游戏目录下的 `mods` 文件夹。

## 启用与停用

- **启用**:模组文件夹里**没有** `disable.it`。
- **停用**:模组文件夹里有一个空的 `disable.it`。

在 Linux 上,游戏只从副本目录加载创意工坊模组,所以启用与停用的效果是这样的:

- 副本里有 `disable.it`:游戏不加载这个模组,文件保留。
- 只有创意工坊源目录里有 `disable.it`,而副本已经存在:游戏忽略它,模组照常加载。
- 副本还没有建立时,创意工坊源目录里的 `disable.it` 会随副本一起复制过去,那个模组同样不会被加载。

因此 SuperDucky 会同时在副本和创意工坊源目录里创建或删除 `disable.it`,让两处保持一致。游戏之后新建的副本也会带着相同的状态。游戏在之后更新创意工坊模组时,是否保留副本里的 `disable.it`,尚未核实。

SuperDucky 只创建或删除这个文件,不改模组里的其它文件,也不删除模组。停用的模组仍然显示在列表里。

同步发生在两个时机:保存分组、切换套件时各同步一次;点击**启动游戏**时再同步一次。

写入时的规则:

- 游戏正在运行时**拒绝写入**,需要先关闭游戏。无法判断游戏是否在运行时,也按“在运行”处理。
- 写入前 SuperDucky 会记住每个 `disable.it` 的原状态。中途失败时,会按记录把已改动的文件恢复。不会生成备份文件。
- 如果写入过程中 SuperDucky 被强制结束,这些改动无法自动恢复。

## 没有加载顺序

以撒的结合没有加载顺序,SuperDucky 也不写入任何顺序。界面上隐藏了与顺序有关的操作:“移到最前”“移到最后”、分组里的上下移动和拖拽排序,以及套件说明中的顺序部分。

分组、启用和停用仍然可用,把模组拖进分组也没有问题。游戏按什么顺序加载模组,SuperDucky 没有检查。

## 没有能力确认

以撒的结合的模组不需要批准能力。启动游戏时不会出现“确认模组能力”的对话框。

## 创意工坊、市场和成就

- **模组市场**:按 Steam 应用 ID 250900 浏览、订阅和取消订阅创意工坊模组。详见[模组市场](/user-guide/marketplace)。
- **ZIP 安装**:从文件夹安装 ZIP 时,SuperDucky 按 `metadata.xml` 识别模组。以撒的结合正在运行时会拒绝安装。
- **成就页**:可用。

## 模组历史与持久套装

模组历史已开启,与[模组本地仓库](/user-guide/mod-local-repository)一起使用。该页默认关闭,需要在设置中为这个游戏打开。

- 模组的文件内容变化(增加、修改或删除文件)时,会记为一个新版本。
- 启用或停用(增删 `disable.it`)**不会**产生新版本。
- 根目录的预览图(例如 `previewpic.jpg`)计入版本,更换预览图会产生新版本。
- 持久套装还原某个版本的内容时,保留每个模组当前的启用状态:还原前已停用的模组,还原后仍然停用。
- 在 Linux 上,历史读写的是游戏实际加载的副本。对已复制的创意工坊模组,“还原版本”写入的是副本,游戏会加载还原后的内容。创意工坊更新后是否覆盖副本里被还原的内容,尚未核实,见下面的已知限制。

## 存档

游戏在 Linux 数据目录里写的存档名是 `<日期>.abp_persistentgamedata1.dat`(实测的是 1 号槽),旁边还有 `options.ini`。SuperDucky 的存档列表按槽位列出 1 到 3 号槽,文件名可以带 `<日期>.` 前缀,也可以带 `rep_`、`rep+` 或 `abp_` 前缀。同一个槽有好几个带日期的文件时,只取最近修改的那一个,其余不算存档。Windows 上的文件名样式(不带日期)尚未在真机上核实。

SuperDucky 只读取存档列表,不修改存档。目前套装绑定存档的功能暂时停用,已有的绑定仍可查看。

## 日志

游戏日志是数据目录里的 `log.txt`(Linux 上已核实)。游戏每次启动都会重写它,而不是接着写,所以它只包含最近一次启动的内容。可以在[游戏日志](/user-guide/logs)页查看。Windows 上的位置尚未在真机上核实。

## 已知限制

- 没有加载顺序,也没有调试接口:SuperDucky 无法确认游戏实际加载了哪些模组,只能看到模组文件夹(Linux 上是副本)里的 `disable.it` 状态。
- Linux 上,历史对有副本的创意工坊模组读写副本;没有副本的模组读写创意工坊源目录。游戏更新创意工坊模组后,是否覆盖副本里被还原的内容尚未核实。
- 取消订阅后,如果游戏留下了副本,副本会显示为本地模组。
- 游戏更新创意工坊模组后,副本里的 `disable.it` 是否保留尚未核实。
- 在部分 Linux 桌面(XWayland)上,游戏本体启动时可能崩溃。这是游戏本身的问题,SuperDucky 不会修改游戏来绕过它。
- 不支持 macOS。
- 标题包目前只收录了少量样本,大多数模组显示的是 `metadata.xml` 中的名称。
- 不支持存档图鉴、NuGet 市场、BML 导入、启动器依赖检查、能力确认和热重载。
- 本页暂时没有界面截图。
